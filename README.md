# 🐺 Wolves Ledger｜灰狼數據帳本

Minnesota Timberwolves 的每日 Synergy PlayType 與 NBA Tracking 數據研究站（另附對戰分析、組合數據、球員比較與薪資頁），設計目標是寫專欄時「找得快、看得準、引用得出去」。

## 功能總覽

開站首頁是最新一場比賽的單場頁（比分看板＋單場分頁），點「← 回主畫面」進主畫面。主畫面由上而下：刊頭（賽季年份／例行·季後／賽程月曆／對戰／組合／薪資／搜尋）→ 頭像列（全隊＋球員）→ 身分列（4 個主數字、「數據截至」日期；球員另顯示該季薪資與「比較」）→ 章節列（六章節＋右側「期間」；Playtype 章節另有「進攻端／防守端」切換，總覽的雷達與單場面板各自帶切換）。

- **賽程月曆**：刊頭「賽程」打開整季（例行＋季後）月曆，有比賽的日子標對手與勝負，點日期看該場 Box Score；本季還沒打的比賽用虛框標出（滑過看台北開賽時間）；過去賽季也能用（單場資料從 2022-23 起）
- **賽前預覽**：還沒打的比賽也能開單場頁——雙方本季數據對照與聯盟名次（1st、2nd…）、休息天數（背靠背）、近三季交手與本季剩餘交手、雙方近 5 場；單場頁賽程條最後一張就是「下一場」
- **完整賽程（`#schedule`）**：本季全部比賽，桌面是月曆格（隊徽、對手、比分或開賽時間、背靠背與盃賽標記）、手機是清單，可依月份與主客場篩選。日期一律美東（跟 NBA 官方一致），開賽時間寫「台北隔日 09:30」。入口：小月曆底部、單場頁右上、搜尋「賽程」
- **期間篩選（全章節共用）**：章節列右側（手機在身分列）的「期間」——全季、勝敗、主客、近 5／10 場、每月、對手、自訂區間、**條件**；選了之後總覽、Splits、投籃、防守都只算這些比賽，換章節也保留。總覽的全隊效率、個人效率、在場／不在場（含節奏），防守章節的防守 Box、全隊最近防守者、對手分區、防守熱圖，投籃的得分組成也跟著期間（由單場數據重算；篩選時不排名，逐場加權的近似值標「≈」；個別沒有逐場資料的格子，如快攻失分，變淡並寫整季值）。只有整季數字的區塊（Clutch、陣容、Playtype、雷達、受助攻、全隊護框）會變淡並標「整季數據 · 篩選時停用」、不能點，不會把沒篩選的數字混進來；複製引用會自動附上期間與場數（如「勝場（8 場）」「2026-11-01 至 2026-11-17（8 場）」）
- **組合數據（`#lineups`）**：二人／三人／五人**全部**組合的上場分鐘與進攻、防守、淨效率、真實命中率；可只看含某幾位球員的組合、設最少分鐘（短時間組合的效率很極端）、二人另有「矩陣」一眼看誰和誰搭得起來。當季每天更新，2022-23 起各季例行賽與季後賽都有。入口：刊頭「組合」、總覽五人陣容「看全部組合」、搜尋
- **球員比較（`#cmp`）**：兩位灰狼球員並排——差距最大的五項（依逐場波動排序）、逐項對照（命中率附成對出手數）、兩人同場的效率與各自在場／不在場、逐場走勢、Playtype；可切場均／每 36 分鐘、近 N 場／勝敗／主客，兩人可各選賽季（如 2024-25 的 A 對 2026-27 的 B）。入口：球員身分列「比較」、搜尋
- **網址記住畫面**：球員、章節、賽季、賽別、日期、攻守、打開的走勢指標、單場比賽都寫進網址，貼到筆記裡下次一點就回到同一畫面。球員寫成「ID-名字」（如 `p=1630162-anthony-edwards`）、賽季寫成 `s=2025-26&t=playoffs`；舊格式的連結仍可開
- **單場比賽頁（Game Center）**：比分看板與每節比分常駐，下方分四頁——概要（本場焦點與 Four Factors、**本場題材**、本場 vs 季平均、比賽資訊）／Box Score（兩隊，可切「傳統｜進階」——進階有進攻／防守／淨效率、使用率、真實命中率等，灰狼球員另有「不在場」效率；點灰狼球員展開本場進階並標出優於季平均的項目，2026-27 起）／對比（球隊對比）／投籃（本場投籃）；用賽程條換場次會停在同一頁；點指標直接看該指標逐場走勢並圈出這場。附加賽場次標「附加賽」，和例行賽平均比較
- **對戰分析（`#vs`）**：交手前瞻用。預設看近三季（本季例行賽未過半時多含一季，避免開季樣本太少），可切只看本季或指定賽季、例行／季後——
  - 首頁：對手總表（戰績、得失分、場均分差，標出**勁敵／順手／棘手**）、指標 × 對手熱圖（灰狼打各隊時哪些數據特別好或差）、單一指標排行（附 95% 波動範圍）、勝負關鍵因子（贏球和輸球時差最多的指標）、灰狼球員 × 對手（誰打哪隊特別好）
  - 單隊頁（`#vs=DEN`）：戰績與主客、最突出的 5 項、交手紀錄、全部指標、每節分差、對手打灰狼（兩隊 box 與對手球員）、灰狼球員打這隊、投籃分布；單場頁可一鍵跳到「與這隊歷次交手」
  - 排序與上色看「偏離程度」（差距 ÷ 場數造成的正常波動），只交手兩三場的極端值不會被誇大；每個數字都標場數。只用既有逐場資料計算；每節分差與對手 box 從 2025-26 起才有
- **薪資頁（Cap Sheet，`#cap`）**：分「總覽／合約／選秀權／規則」四頁——
  - 總覽：所在層級、是否鎖死在 apron（hard cap）、奢侈稅率（依繳稅紀錄自動判定是否累犯），奢侈稅薪資／apron 薪資／各門檻空間、門檻儀表、奢侈稅分級估算
  - 合約：逐年薪資總表（往後 5 季、選項與保障標記、點球員名開球員頁）、薪資結構、薪資占比 vs 貢獻占比（公式常駐、可關閉）
  - 選秀權：2027 起各年首輪／次輪狀態，可展開原文條件與出處
  - 規則：超過薪資帽／奢侈稅線／第一、第二 apron 會受到的操作限制，附出處
  - 縮寫金額滑鼠移上去顯示完整金額；資料人工整理自 Spotrac、Hoops Rumors 等公開資料，與 Spotrac 逐元對帳
- **快捷鍵**：`/` 搜尋球員／章節／賽季／最近比賽／賽程（下一場、完整賽程）／對戰（打隊伍三碼，如 `DEN`）／組合數據／球員比較／薪資；數字鍵切目前畫面的分頁（主畫面 `1–6` 章節、單場頁 `1–4`、薪資頁 `1–4`）
- **複製引用**：點數字旁的「?」看定義，小卡內可一鍵複製「球員｜賽季｜截至日期｜指標 數值｜資料來源｜畫面網址」
- **聯盟名次**：全隊數據（身分列、季平均、全隊效率、Clutch、防守、Splits「全季」）下方標「聯盟第N」（30 隊，當季每日更新）；球隊 Playtype 由百分位換算名次。**球員也有**：在全聯盟合格球員（出賽 ≥ 球隊場數 70%、每場 ≥ 15 分鐘）中排名，命中率類另有場均出手門檻（投籃 5、三分 3、罰球 2 次），前 30 名綠字；沒有名次時「?」小卡會說明原因。總覽另有「全隊效率」（OffRtg／DefRtg／NetRtg／Pace／TS% 等）
- **本場題材（找題材用）**：單場頁概要自動列出這場值得寫的點——勝負關鍵（Four Factors 加權貢獻最大的一項）＋最多 5 個題材（本季新高、2022-23 起的排名、本季最佳／最低），附前一筆紀錄是哪一場；名次截至當場，之後被超越的會標灰並註明；每項可複製引用或加入引用籃
- **條件戰績**：期間選「條件」，設最多 2 個條件（某球員〈指標〉≥／≤ 數值、全隊〈指標〉、某球員有／未出賽），看符合場次的戰績、勝率、場均分差，和其他場次對照；例如「A. Edwards 得分≥30 時 18-14（其他 31-19）」。網址記住條件，可分享、可加入引用籃；當季仍在名冊上的球員，傷停缺陣也算進「未出賽」
- **歷史定位（這數字算多嗎）**：單場頁「本場 vs 季平均」只在球員打出灰狼場次（2022-23 起）前 3 名的格子標「灰狼第 2 高」；Box Score 展開列每項的「?」點開看完整定位——第幾名與前幾 %、或「中段」、「自 X 以來最高」，引用時一併帶上
- **引用籃（貼文用純文字）**：在各頁「?」小卡「加入引用籃」收集數值或比較（Splits 期間、跨季、On/Off、單場），右下角抽屜最上面是分段預覽，每段可單獨複製（數據段分散在各小節時一段一段貼），也能一鍵複製全部；展開「項目」排順序、把出手數＋命中率併成一行（自動排成「出手數／命中率」）、把同一指標在不同條件或期間的兩項「合成比較」（例：「未出賽 vs. 有出賽」「全季 → 近 10 場」），展開「格式」選※行首、段首要不要「●」、名次、→／差值／📈📉、依球員或依指標分段
- **戰報引用**：單場頁「球隊對比」（含四因素、投籃分區）可整組或逐列加入引用籃，寫成「灰狼 vs. 對手」並列；Box Score 展開球員可把整場數據排成一行加入（對手球員也可以，寫成「Toumani Camara（拓荒者）」）；引用籃標頭可選「單場比分」（`@ 休士頓火箭 117:107 灰狼勝`，例行賽與季後賽都帶場次如 `G14 vs. 波特蘭拓荒者`，可附每節比分）
- **單場 Playtype（`#game=日期&tab=pt`）**：單場頁「Playtype」分頁列出灰狼全隊這場各戰術的回合數、頻率、每回合得分（防守端：對手每回合得分）與賽前季均，綠紅標出好壞；逐列或整組加入引用籃，寫成「※轉換進攻 回合數／每回合得分：22.3／1.15 → 26／1.42」。Synergy 沒有單場數據，由每日快照前後相減還原（2026-27 起；某天快照漏抓的兩場會合在一起、顯示無資料）。只有全隊，沒有個人與百分位
- **指標定義**：指標旁的「?」說明定義、計算方式與資料來源
- **匯出**：表格可匯出 CSV（Excel 可直接開），圖表與表格可匯出 16:9／1:1 PNG 專欄配圖
- **加到手機主畫面**：iPhone 用 Safari「分享 → 加入主畫面」、Android 用 Chrome「安裝應用程式」，以「灰狼帳本」圖示開啟、沒有網址列
- **無障礙**：文字對比符合 WCAG AA、按鈕點擊範圍至少 24px、鍵盤操作有焦點框（PageSpeed 無障礙 100）

## 技術概要

- **前端**：靜態網頁（GitHub Pages），React 18 鎖版本 CDN，JSX 與 Tailwind 由 `scripts/bundle.py` 事先編譯成 `dist/`；圖表全部自繪 SVG
- **資料**：Firebase Firestore（前端用 Firestore lite 匿名讀取）
- **抓取**：Python 腳本在本機 Windows 工作排程器執行（GitHub Actions 的機房 IP 會被 NBA 擋）
- **薪資**：人工維護的 Google Sheet，每日同步進 Firestore

```
NBA Stats API ──(Python, 本機排程)──▶ Firebase Firestore ◀──(JS)── index.html (GitHub Pages)
                每日 03:00（15:00 看門狗補抓）/ 每週一 14:30   Firestore lite 讀取（開站先讀近期快照）

Google Sheet（人工維護薪資）──(sync_salary.py，每日順跑)──▶ Firestore wolves_salary/main
```

檔案結構、資料結構、排程細節、FAQ 與維護方式見 [`doc/handover.md`](doc/handover.md)；各功能的設計過程見 [`doc/history.md`](doc/history.md)。

## 快速開始

### 本地測試爬蟲

```bash
pip install -r requirements.txt   # 含 tzdata（Windows 沒有系統時區資料庫，美東時間要用）
python scripts/fetch_data.py
# 無 Firebase 環境時會輸出 local_test_data.json
```

### 自動化測試

```bash
# 後端（unittest）＋前端（node:test），零新依賴、0 個 NBA／Firestore request
python scripts/run_tests.py
```

### 本地預覽前端

```bash
# 新電腦第一次：安裝建置工具（需 Node.js）
npm ci
# 改過 components/ 之後先重新打包
python scripts/bundle.py
# 任何靜態伺服器即可；用 8000 埠（Firebase API Key 的網址白名單只開 localhost:8000）
python -m http.server 8000
```

## 部署設定

- **排程**：Windows 工作排程器四個工作——`WolvesTracker`（每日 03:00 抓取＋薪資同步）、`WolvesWatchdog`（15:00 看門狗補抓）、`WolvesWatchdogMorning`（早上補跑主排程）、`WolvesShotchart`（每週一投籃熱圖）；建立指令與設定見 handover「自動化排程」
- **Firebase**：專案 `wolves-traker`；本地寫入憑證 `firebase-key.json`（在 .gitignore，勿提交）；安全規則為匿名讀取、後端寫入。**新增集合必在 Console 加 read 白名單與 `*` 索引豁免**，集合清單見 handover「Firebase 設定」「Firebase 資料結構」
- **GitHub Pages**：`main` 分支根目錄直接部署 `index.html`
